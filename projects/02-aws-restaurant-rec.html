01 專案背景與核心挑戰 (Context & Problem)

現代使用者在搜尋美食時，往往面臨傳統地圖評分膨脹、關鍵字篩選死板（難以理解複雜語義如「適合多人聚餐、安靜且預算五百內的平價火鍋」）以及在聊天機器人文字與地理地圖之間反覆切換的破碎體驗。

本專案目標是打造一個**全端整合、具備語意理解力與無縫地圖互動**的智慧餐廳推薦系統，讓使用者能直接以口語對話，即時獲得附帶評分、推薦原因、位置標記的結構化清單。

02 系統架構與工程設計 (System Architecture)

全系統採標準 AWS 雲端無伺服器微服務架構，兼顧低延遲與高擴充彈性：

// 完整雲端數據與互動流向
• 前端託管：S3 儲存靜態檔案，經由 CloudFront CDN 提供全球低延遲 HTTPS 存取。
• API 通訊：Client 發送 RESTful 請求至 AWS API Gateway，由 Lambda 進行後端運算。
• 智慧推理：Lambda 透過 boto3 調用 Amazon Bedrock (Nova Micro Model)，結合 Google Places API 資訊進行動態 Prompt 生成與語意排序。
• 資料快取與推播：餐廳資訊快取於 Amazon DynamoDB；週報與通知由 Amazon EventBridge 定時觸發 SNS 與 SES。
• 前端地圖呈現：Google Maps JavaScript API 載入向量地圖，依據推薦結果動態繪製 Markers。

03 關鍵功能與工程亮點 (Key Highlights)

雙向聯動互動地圖

使用者在對話框點選特定餐廳，地圖即時自動平移並聚焦（panTo & zoomIn）；反之，點擊地圖上的 Marker 也會同步高亮側邊欄的推薦理由。

Bedrock 語意分析推薦

結合 Amazon Bedrock Nova Micro 模型，精準理解使用者輸入的模糊情境（如「聚餐」、「氣氛好」、「咖啡好喝」），提供量身訂做的推薦理由。

個人化收藏與偏好記錄

支援即時收藏餐廳、自訂標籤分類，並在下次推薦時作為 Context 輸入給 LLM，讓模型推薦越用越準確。

自動化熱門週報推播

結合 EventBridge、SNS 與 SES，定時發送個人化周遭熱門餐廳探索清單，建立完整的用戶喚醒與回訪閉環。

04 成效指標與量化表現 (Impact & Verification)

  • 高可靠且成本優化的 Serverless 架構： 全站無常駐 EC2 伺服器，依靠 Lambda 與 DynamoDB 按量計費，在無流量時維持零運算成本。
  • 極致流暢的前端互動體驗： 藉由 CloudFront CDN 快取與輕量化的純前端 JavaScript 介面，靜態資源載入時間在 300ms 內完成。
